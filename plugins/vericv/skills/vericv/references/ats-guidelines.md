# ATS-friendly formatting guidelines

- Prefer a single-column, text-based document with conventional headings: Summary, Skills, Experience, Projects, Education, Certifications.
- Use a readable font and consistent dates; avoid tables, text boxes, icons, graphics, headers/footers containing essential information, and multi-column layouts.
- Use standard job titles and truthful relevant keywords naturally in skills and evidence-bearing bullets.
- Put the most relevant supported evidence near the top. Do not keyword-stuff or repeat skills without evidence.
- Use reverse-chronological experience unless the user requests another structure. Preserve source dates and employment facts.
- Keep contact details minimal and candidate-provided. Do not add a photo, birth date, marital status, or identifiers unless the user explicitly requests and supplies them.
- Treat page count as a layout constraint, not a reason to add unsupported claims or leave large empty areas. Read `layout-quality.md` before producing a CV file.
- A good format improves parseability; it cannot guarantee how any employer system will rank the document.
